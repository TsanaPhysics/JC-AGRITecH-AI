## 1. ระบบนี้คืออะไร

ระบบนี้ใช้ตรวจวัดสภาพแปลงเกษตรและสั่งเปิด-ปิดอุปกรณ์ (เช่น ปั๊มน้ำ วาล์ว ระบบพ่นหมอก) จากระยะไกล แบ่งเป็น 3 ส่วน

- **บอร์ด ESP32** — อยู่ที่แปลง อ่านค่าจากเซนเซอร์ แสดงผลบนจอสัมผัส และสั่งเปิด-ปิดรีเลย์ 4 ช่อง
- **เซิร์ฟเวอร์** — เว็บที่อยู่บนอินเทอร์เน็ต ทำหน้าที่เป็นตัวกลางเก็บข้อมูลและคำสั่ง (ที่อยู่: `https://scicenter.rbru.ac.th/leqs-workshop/`)
- **แดชบอร์ด** — หน้าเว็บที่เปิดดูข้อมูลและกดสั่งงานจากคอมพิวเตอร์หรือมือถือ

```
 บอร์ด ESP32  ──ส่งข้อมูล──▶  เซิร์ฟเวอร์  ◀──ดึงข้อมูล──  แดชบอร์ด (เบราว์เซอร์)
 (แปลงเกษตร)  ◀──รับคำสั่ง──   (มหาวิทยาลัย)  ◀──ส่งคำสั่ง──  (บ้าน/มหาวิทยาลัย)
```

หลักการสำคัญ: บอร์ดกับแดชบอร์ดไม่ได้คุยกันโดยตรง แต่คุยผ่านเซิร์ฟเวอร์ จึงอยู่คนละเครือข่าย Wi-Fi ได้

## 2. คำศัพท์ที่ควรรู้

| คำ | ความหมายแบบง่าย |
|---|---|
| Wi-Fi / SSID | ระบบอินเทอร์เน็ตไร้สาย / ชื่อของ Wi-Fi นั้น |
| IP | ที่อยู่ของอุปกรณ์ในเครือข่าย (เช่น `10.24.89.144`) |
| URL | ที่อยู่ของหน้าเว็บ (เช่น `https://scicenter.rbru.ac.th/...`) |
| รีเลย์ | สวิตช์ไฟฟ้าที่บอร์ดสั่งเปิด-ปิดอุปกรณ์ มี 4 ช่อง |
| แดชบอร์ด | หน้าเว็บแสดงค่าเซนเซอร์และปุ่มสั่งงาน |
| Manual / SMART AUTO / EDGE AI | โหมดควบคุม: สั่งเอง / ตามกฎอัตโนมัติ / ตามโมเดล AI บนบอร์ด |
| พอร์ทัลตั้งค่า | หน้าตั้งค่า Wi-Fi ที่บอร์ดเปิดขึ้นเอง ชื่อ `LEQs-AgriEnvi-Setup` |
| Token | รหัสลับที่บอร์ดแนบไปด้วย เพื่อยืนยันกับเซิร์ฟเวอร์ว่าเป็นบอร์ดของเรา |
| FileZilla | โปรแกรมอัปโหลดไฟล์ขึ้นเซิร์ฟเวอร์ |
| PlatformIO | โปรแกรมใน VS Code ใช้ใส่โปรแกรมลงบอร์ด |
| Serial Monitor | หน้าต่างดูข้อความที่บอร์ดพิมพ์ออกมา ใช้ตรวจว่าบอร์ดทำงานปกติ |

## 3. สิ่งที่ต้องเตรียม

- บอร์ด ATD3.5-S3 (ESP32-S3) พร้อมเซนเซอร์ที่ต่อแล้ว
- สาย USB ที่ส่งข้อมูลได้ (สายชาร์จอย่างเดียวใช้ไม่ได้)
- คอมพิวเตอร์ที่ติดตั้ง VS Code และส่วนเสริม PlatformIO
- โปรแกรม FileZilla และบัญชี FTP ของเซิร์ฟเวอร์
- Wi-Fi หรือฮอตสปอตมือถือที่บอร์ดใช้ (ความถี่ 2.4 GHz เท่านั้น)

## 4. ติดตั้งครั้งแรก (ทำตามลำดับ)

### ขั้นที่ 1 อัปโหลดเว็บขึ้นเซิร์ฟเวอร์

1. เปิด FileZilla เชื่อมต่อเซิร์ฟเวอร์
2. ฝั่งซ้าย (เครื่องเรา): โฟลเดอร์ `handysense/leqs-workshop`
3. ฝั่งขวา (เซิร์ฟเวอร์): โฟลเดอร์ `/public/leqs-workshop`
4. ลากอัปโหลดโฟลเดอร์ `api` และ `dashboard` ทับของเดิม
5. ตั้งสิทธิ์โฟลเดอร์ `data` ให้เซิร์ฟเวอร์เขียนไฟล์ได้: คลิกขวา → File permissions → ใส่ `775` (ถ้ายังไม่ได้ผลให้ใช้ `777`)
6. ทดสอบ: เปิด `https://scicenter.rbru.ac.th/leqs-workshop/api/api.php?action=get_commands` ต้องเห็นข้อความขึ้นต้น `{"status":"success"...`

หมายเหตุ: URL ที่ใช้งานจริง **ไม่มีคำว่า `/public`** แม้โฟลเดอร์บนเซิร์ฟเวอร์จะอยู่ใต้ `/public`

### ขั้นที่ 2 ใส่โปรแกรมลงบอร์ด

1. เสียบ USB เข้าบอร์ดและคอมพิวเตอร์
2. เปิด VS Code → **File → Open Folder** → เลือกโฟลเดอร์ `esp32-board`
3. กดไอคอน **✓ (Build)** รอจนขึ้น `SUCCESS`
4. กดไอคอน **→ (Upload)** รอจนขึ้น `SUCCESS`
5. กดไอคอนเต้ารับ (Serial Monitor) เพื่อดูข้อความจากบอร์ด

ถ้าอัปโหลดไม่ผ่านดูหัวข้อ 8

### ขั้นที่ 3 ตั้งค่า Wi-Fi และที่อยู่เซิร์ฟเวอร์ให้บอร์ด

1. ถ้าบอร์ดต่อ Wi-Fi ไม่ได้ ประมาณ 45 วินาที บอร์ดจะเปิด Wi-Fi ชื่อ `LEQs-AgriEnvi-Setup` ขึ้นมาเอง (หรือเปิดจากหน้า SETUP บนจอบอร์ด)
2. ใช้มือถือหรือคอมพิวเตอร์เชื่อมต่อ Wi-Fi ชื่อนั้น แล้วเปิดหน้าตั้งค่าที่ขึ้นมา
3. เลือกชื่อ Wi-Fi (หรือฮอตสปอตมือถือ) และใส่รหัสผ่าน
4. ช่อง Dashboard URL ใส่
   `https://scicenter.rbru.ac.th/leqs-workshop/api/api.php?action=update_telemetry`
5. บันทึก แล้วรอบอร์ดเชื่อมต่อใหม่

### ขั้นที่ 4 (ไม่บังคับ แต่แนะนำ) ตั้ง Token กันข้อมูลปลอม

ต้องตั้ง **รหัสเดียวกันสองที่** และทำให้เสร็จก่อนใช้งานจริง

1. คิดรหัส 1 ชุด ตัวอักษรอังกฤษและตัวเลขล้วน ยาวๆ ไม่มีเว้นวรรค
2. สร้างไฟล์ข้อความชื่อ `device_token.txt` ข้างในใส่รหัสนั้นบรรทัดเดียว อัปโหลดไปที่ `/public/leqs-workshop/data/`
3. เปิดไฟล์ `esp32-board/include/UserConfigs.h` แก้บรรทัด `#define DEVICE_TOKEN ""` ให้เป็น `#define DEVICE_TOKEN "รหัสของคุณ"`
4. ทำขั้นที่ 2 (Upload) ซ้ำเพื่อใส่โปรแกรมลงบอร์ดอีกครั้ง

ถ้าตั้งแล้วแดชบอร์ดขึ้น OFFLINE ให้ลบไฟล์ `device_token.txt` ออกจากเซิร์ฟเวอร์ชั่วคราว แล้วตรวจว่ารหัสสองที่ตรงกันหรือไม่

### ขั้นที่ 5 ทดสอบ

1. เปิด `https://scicenter.rbru.ac.th/leqs-workshop/dashboard/index.php`
2. มุมบนต้องขึ้นสถานะ **LIVE** สีเขียว และตัวเลขเซนเซอร์เปลี่ยนไปเรื่อยๆ
3. ลองกดสวิตช์รีเลย์ 1 ตัว (ถอดอุปกรณ์ไฟฟ้าออกก่อนทดสอบครั้งแรก) ภายใน 1–3 วินาที ควรได้ยินเสียงรีเลย์ดังคลิก

## 5. ใช้งานหน้าแดชบอร์ดประจำวัน

### 5.1 แถบสถานะด้านบน

| สถานะ | ความหมาย | ต้องทำอะไร |
|---|---|---|
| **LIVE** (เขียว) | ได้รับข้อมูลจากบอร์ดล่าสุดภายในประมาณ 6 วินาที | ปกติ |
| **DELAYED** (เหลือง) | ข้อมูลล่าช้า 6–20 วินาที | รอสักครู่ ถ้ายังเหลืองให้ตรวจสัญญาณ Wi-Fi |
| **OFFLINE** (แดง) | ไม่ได้ข้อมูลเกิน 20 วินาที หรือเชื่อมต่อเซิร์ฟเวอร์ไม่ได้ | ดูหัวข้อ 8 (ค่าที่เห็นเป็นค่าเก่า ห้ามใช้ตัดสินใจ) |

ข้างสถานะแสดง "กี่วินาทีที่แล้ว" ของข้อมูล และเวลาตอบสนองของเซิร์ฟเวอร์

### 5.2 การ์ดค่าเซนเซอร์ 6 ใบ

- **สภาพอากาศ (SHT45):** อุณหภูมิและความชื้นสัมพัทธ์ มีแถบกราฟเล็กแสดงแนวโน้ม
- **แรงดึงระเหยน้ำ (VPD):** บอกว่าอากาศแห้งหรือชื้นเกินไป แถบสีเขียวคือช่วงเหมาะสม (0.8–1.2 kPa)
- **ความชื้นในดิน:** ผิวดินและเขตราก ช่วงเหมาะสมคือ 40–65%
- **กรด-ด่างดิน (pH):** ช่วงเหมาะสมคือ 5.5–7.5 พร้อมค่า N, P, K
- **แสงแดดและรังสี:** ความเข้มแสงเป็น Lux
- **การจัดเก็บข้อมูล 2 ชั้น:** จำนวนเรคอร์ดใน SD Card และฐานข้อมูล

ตัวเลขที่ไม่มีข้อมูลจะแสดง `--` (ระบบไม่แสดงค่าปลอม)

### 5.3 กราฟแนวโน้ม

- แสดงอุณหภูมิ ความชื้น และความชื้นดิน ย้อนหลังจากฐานข้อมูล และเพิ่มจุดใหม่ทุกครั้งที่บอร์ดส่งข้อมูล
- กดปุ่ม Temp / Humidity / Soil Moist เพื่อซ่อนหรือแสดงแต่ละเส้น

### 5.4 สั่งรีเลย์ 4 ช่อง

1. กดสวิตช์ข้างชื่ออุปกรณ์ (เลื่อนไปทางขวา = เปิด)
2. สวิตช์เปลี่ยนทันที แล้วระบบรอให้บอร์ดยืนยัน ถ้าสั่งไม่สำเร็จ สวิตช์จะเด้งกลับพร้อมข้อความแจ้ง
3. ปุ่ม **ปิดทั้งหมด** ใช้ปิดรีเลย์ทุกช่องที่เปิดอยู่ในครั้งเดียว
4. คำสั่งจะถึงบอร์ดภายในประมาณ 1–3 วินาที (ไม่ใช่ทันที)

### 5.5 โหมดควบคุม

| โหมด | การทำงาน |
|---|---|
| **Manual** | สั่งเปิด-ปิดเองทั้งหมด |
| **Auto (SMART AUTO)** | บอร์ดเปิด-ปิดตามกฎเงื่อนไขที่ตั้งไว้ |
| **AI Smart (EDGE AI)** | บอร์ดตัดสินใจโดยโมเดล AI |

การกดสวิตช์รีเลย์ด้วยตัวเองจะสลับกลับเป็นโหมด Manual อัตโนมัติ เพื่อไม่ให้ระบบอัตโนมัติสั่งทับ

### 5.6 เมนูด้านบน

- **จำลองจอ ESP32:** ดูหน้าจอบอร์ดจำลองบนเว็บ
- **QR Portal:** แสดง QR Code สำหรับเปิดระบบ
- **Mobile:** เปิดหน้าสำหรับมือถือ
- **เพิ่มเติม:** ตั้งค่า IP บอร์ด, ดาวน์โหลด CSV, โหลด APK, กลับเว็บหลัก

## 6. ใช้งานจอสัมผัสของบอร์ด

แถบเมนูด้านบนของจอมี 6 หน้า ได้แก่ **1. HOME, 2. DATA, 3. GRAPH, 4. RELAY, 5. SETUP** และ **ENG** (สลับภาษา)

- แตะแถบเมนูเพื่อเปลี่ยนหน้า
- หน้า **RELAY:** แตะที่กล่องรีเลย์เพื่อเปิด-ปิด (ระบบจะเข้าโหมด Manual)
- หน้า **GRAPH:** ดูกราฟย้อนหลัง
- หน้า **SETUP:** เปิด-ปิดพอร์ทัลตั้งค่า Wi-Fi
- เมื่อแตะ จะมีกรอบสีขาวขึ้นทันทีเพื่อยืนยันว่าบอร์ดรับการแตะแล้ว
- การเปลี่ยนรีเลย์จากแดชบอร์ดจะสะท้อนบนจอบอร์ดเองภายในไม่กี่วินาที

หมายเหตุ: เฟิร์มแวร์เวอร์ชันปรับปรุงวันที่ 2026-10-08 (ทัชเร็วขึ้น และรับคำสั่งข้ามเครือข่ายเร็วขึ้น) ยังอยู่ระหว่างทดสอบบนบอร์ดจริง หากพบอาการผิดปกติให้แจ้งผู้ดูแล

## 7. สั่งงานข้ามเครือข่าย (บอร์ดใช้ฮอตสปอตมือถือ)

**สถานการณ์:** บอร์ดต่อฮอตสปอตมือถือ ส่วนคอมพิวเตอร์ต่อ Wi-Fi บ้านหรือมหาวิทยาลัย

**ทำได้หรือไม่:** ทำได้ ถ้าครบ 3 ข้อ

1. บอร์ดมีอินเทอร์เน็ต (ฮอตสปอตมีสัญญาณและเปิดใช้งานข้อมูลมือถือ)
2. บอร์ดตั้ง Dashboard URL เป็นที่อยู่เซิร์ฟเวอร์สาธารณะ (ขั้นที่ 3)
3. เปิดแดชบอร์ดจาก URL ของเซิร์ฟเวอร์ ไม่ใช่ `localhost`

**ทำไมต้องผ่านเซิร์ฟเวอร์:** อุปกรณ์คนละเครือข่ายมองไม่เห็นกันโดยตรง (รายละเอียดอธิบายไว้ใน `MANUAL_IOT_CROSS_NETWORK_GUIDE.md` หัวข้อ 1)

**ข้อจำกัด:** คำสั่งจากแดชบอร์ดถึงบอร์ดช้ากว่าการต่อ Wi-Fi เดียวกัน ประมาณ 1–3 วินาที และใช้ข้อมูลอินเทอร์เน็ตของฮอตสปอตเล็กน้อยตลอดเวลา

## 8. แก้ปัญหาเบื้องต้น

| อาการ | สาเหตุที่เป็นไปได้ | วิธีแก้ |
|---|---|---|
| เปิดหน้าแดชบอร์ดขึ้น HTTP ERROR 500 | ไฟล์บนเซิร์ฟเวอร์เปิดอ่านไม่ได้ (สิทธิ์ไฟล์ผิด) หรือไฟล์ที่อัปโหลดไม่ครบ | ใน FileZilla ตั้งสิทธิ์ไฟล์ `.php` เป็น `644` และโฟลเดอร์เป็น `755` แล้วอัปโหลดใหม่ ถ้ายังไม่หายให้ขอดู `php_error_log` จากผู้ดูแลเซิร์ฟเวอร์ |
| สถานะ OFFLINE | บอร์ดไม่ส่งข้อมูล | ตรวจว่าบอร์ดมีไฟ ตรวจ Wi-Fi/ฮอตสปอตว่ามีอินเทอร์เน็ต ตรวจ Dashboard URL ในพอร์ทัล |
| ค่าเซนเซอร์ไม่เปลี่ยน | โฟลเดอร์ `data` เขียนไม่ได้ | ตั้งสิทธิ์โฟลเดอร์ `data` เป็น `775` หรือ `777` |
| กดสวิตช์แล้วเด้งกลับ | เซิร์ฟเวอร์ไม่ตอบหรือเขียนไม่ได้ | ตรวจอินเทอร์เน็ตของคอม และสิทธิ์โฟลเดอร์ `data` |
| กดสวิตช์แล้วรีเลย์ไม่ติด | บอร์ดยังไม่ได้ใส่โปรแกรมเวอร์ชันใหม่ หรือบอร์ดไม่มีอินเทอร์เน็ต | ดู Serial Monitor ต้องเห็น `[RelayActuator]` หลังสั่ง ถ้าไม่เห็นให้ทำขั้นที่ 2 ซ้ำ |
| Serial Monitor ขึ้นรหัส 401 | Token สองฝั่งไม่ตรงกัน | แก้ให้ตรงกัน หรือลบไฟล์ `device_token.txt` ชั่วคราว |
| อัปโหลดโปรแกรมไม่ผ่าน (ไม่เจอพอร์ต) | สาย USB ไม่ส่งข้อมูล / พอร์ตเสีย | เปลี่ยนสายหรือพอร์ต USB ปิด Serial Monitor ก่อนอัปโหลด |
| อัปโหลดไม่ผ่าน (Failed to connect) | บอร์ดไม่อยู่ในโหมดรับโปรแกรม | กดปุ่ม BOOT ค้าง → กด RESET หนึ่งครั้ง → ปล่อย BOOT แล้วอัปโหลดใหม่ |
| บอร์ดต่อ Wi-Fi ไม่ได้ | รหัสผ่านผิด หรือเป็น Wi-Fi 5 GHz | ใช้ Wi-Fi 2.4 GHz รอ 45 วินาทีให้พอร์ทัลเปิด แล้วตั้งค่าใหม่ |
| ตั้งค่าไว้แล้วหายหลังอัปโหลดโปรแกรม | มีการสั่ง Erase Flash | ตั้ง Wi-Fi และ Dashboard URL ใหม่ผ่านพอร์ทัล |

## 9. ข้อควรระวังด้านความปลอดภัย

- **ไฟฟ้า:** รีเลย์ควบคุมอุปกรณ์ไฟฟ้า ปิดไฟและถอดปลั๊กก่อนต่อหรือแก้สายทุกครั้ง ผู้ที่ไม่มีความรู้ด้านไฟฟ้าควรให้ผู้เชี่ยวชาญต่อสายแรงดันสูง
- **ทดสอบแบบไม่มีโหลด:** ครั้งแรกทดสอบรีเลย์โดยไม่ต่อปั๊มหรือวาล์ว ฟังเสียงคลิกอย่างเดียว
- **การป้องกันแดชบอร์ด:** ตอนนี้ใครรู้ URL ของแดชบอร์ดก็สั่งรีเลย์ได้ ควรตั้งรหัสผ่านให้โฟลเดอร์ผ่านเมนู "Password Protect Directories" ของเซิร์ฟเวอร์ (ถ้ามี) หรือสอบถามผู้ดูแลระบบ
- **Token:** อย่าเผยแพร่รหัส Token และอย่าอัปโหลดไฟล์ `UserConfigs.h` ที่มีรหัส Wi-Fi หรือ Token ขึ้นที่สาธารณะ
- **เมื่อสถานะ OFFLINE:** ค่าที่เห็นเป็นค่าเก่า ห้ามใช้ตัดสินใจรดน้ำหรือควบคุมอุปกรณ์
