## 1. ระบบนี้คืออะไร

ระบบนี้ใช้ตรวจวัดสภาพแปลงเกษตรและสั่งเปิด-ปิดอุปกรณ์ (ปั๊มน้ำ วาล์ว ระบบพ่นหมอก) จากระยะไกล แบ่งเป็น 3 ส่วน

- **บอร์ด ESP32** — อยู่ที่แปลง อ่านค่าเซนเซอร์ แสดงผลบนจอสัมผัส และสั่งรีเลย์ 4 ช่อง
- **เซิร์ฟเวอร์** — เว็บบนอินเทอร์เน็ต เป็นตัวกลางเก็บข้อมูลและคำสั่ง (`https://scicenter.rbru.ac.th/leqs-workshop/`)
- **แดชบอร์ด / หน้ามือถือ** — หน้าเว็บสำหรับดูข้อมูลและกดสั่งงานจากคอมพิวเตอร์หรือมือถือ

```
 บอร์ด ESP32  ──ส่งข้อมูลทุก ~1.5 วินาที──▶  เซิร์ฟเวอร์  ◀──ดึงข้อมูล/ส่งคำสั่ง──  แดชบอร์ด
 (แปลงเกษตร)  ◀──ถามหาคำสั่งทุก 1 วินาที──   (scicenter)
```

หลักการสำคัญ: บอร์ดกับแดชบอร์ดไม่ได้คุยกันโดยตรง แต่คุยผ่านเซิร์ฟเวอร์ จึงอยู่คนละเครือข่าย Wi-Fi ได้ คำสั่งจึงถึงบอร์ดช้ากว่าเดิมประมาณ 1–3 วินาที

## 2. คำศัพท์ที่ควรรู้

| คำ | ความหมายแบบง่าย |
|---|---|
| Wi-Fi / SSID | อินเทอร์เน็ตไร้สาย / ชื่อของ Wi-Fi นั้น |
| IP | ที่อยู่ของอุปกรณ์ในเครือข่าย (เช่น `10.24.89.144`) |
| URL | ที่อยู่ของหน้าเว็บ |
| รีเลย์ | สวิตช์ไฟฟ้าที่บอร์ดสั่งเปิด-ปิดอุปกรณ์ มี 4 ช่อง |
| แดชบอร์ด | หน้าเว็บแสดงค่าเซนเซอร์และปุ่มสั่งงาน |
| Manual / SMART AUTO / EDGE AI | โหมดควบคุม: สั่งเอง / ตามกฎอัตโนมัติ / ตามโมเดล AI บนบอร์ด |
| พอร์ทัลตั้งค่า | หน้าตั้งค่า Wi-Fi ที่บอร์ดเปิดขึ้นเอง ชื่อ `LEQs-AgriEnvi-Setup` |
| `DASHBOARD_URL` | ที่อยู่เซิร์ฟเวอร์ที่ตั้งไว้ในเฟิร์มแวร์ บอร์ดใช้ส่งข้อมูลและรับคำสั่ง |
| `DEVICE_TOKEN` / Token | รหัสลับที่บอร์ดแนบไป เพื่อยืนยันกับเซิร์ฟเวอร์ว่าเป็นบอร์ดของเรา |
| FileZilla | โปรแกรมอัปโหลดไฟล์ขึ้นเซิร์ฟเวอร์ |
| PlatformIO | ส่วนเสริมของ VS Code ที่ใช้ใส่โปรแกรมลงบอร์ด |
| Serial Monitor | หน้าต่างดูข้อความที่บอร์ดพิมพ์ออกมา ใช้ตรวจว่าบอร์ดทำงานปกติ |
| Mixed Content | เบราว์เซอร์บล็อกหน้า HTTPS ไม่ให้เรียกที่อยู่ HTTP (พบในข้อความเตือนของ Console ไม่ใช่ความเสียหาย) |

## 3. สิ่งที่ต้องเตรียม

- บอร์ด ATD3.5-S3 (ESP32-S3) พร้อมเซนเซอร์ที่ต่อแล้ว
- สาย USB ที่ส่งข้อมูลได้ (สายชาร์จอย่างเดียวใช้ไม่ได้)
- คอมพิวเตอร์ที่ติดตั้ง VS Code และส่วนเสริม PlatformIO
- โปรแกรม FileZilla และบัญชี FTP ของเซิร์ฟเวอร์
- Wi-Fi หรือฮอตสปอตมือถือ ความถี่ 2.4 GHz ที่บอร์ดใช้
- Micro-SD Card (ใส่ก่อนจ่ายไฟ เพื่อบันทึกข้อมูลสำรอง)

## 4. ติดตั้งครั้งแรก (ทำตามลำดับ)

### ขั้นที่ 1 อัปโหลดเว็บขึ้นเซิร์ฟเวอร์

1. เปิด FileZilla เชื่อมต่อเซิร์ฟเวอร์
2. ฝั่งซ้าย (เครื่องเรา): `/Applications/XAMPP/xamppfiles/htdocs/handysense/leqs-workshop`
3. ฝั่งขวา (เซิร์ฟเวอร์): `/public/leqs-workshop`
4. ลากโฟลเดอร์ `api`, `dashboard`, `mobile` อัปโหลดทับของเดิม
5. ตั้งสิทธิ์โฟลเดอร์ `data` ให้เขียนได้: คลิกขวา → File permissions → `775` (ถ้าไม่ได้ผลให้ใช้ `777`) ระบบจะสร้างไฟล์ `state.lock` และ `telemetry_state.json` ในโฟลเดอร์นี้
6. ตั้งสิทธิ์ไฟล์ `.php` เป็น `644` (ถ้าเปิดเว็บแล้วขึ้น HTTP 500 ให้ตรวจสิทธิ์ก่อน)
7. ทดสอบ: เปิด `https://scicenter.rbru.ac.th/leqs-workshop/api/api.php?action=get_commands` ต้องเห็นข้อความขึ้นต้น `{"status":"success"...`

หมายเหตุ: URL ที่ใช้งานจริง **ไม่มีคำว่า `/public`** แม้โฟลเดอร์บนเซิร์ฟเวอร์จะอยู่ใต้ `/public`

### ขั้นที่ 2 ตั้งค่าเฟิร์มแวร์ในไฟล์ `UserConfigs.h`

เปิดไฟล์ `esp32-board/include/UserConfigs.h` ใน VS Code แล้วตรวจ 4 จุดนี้

| ค่า | ต้องตั้งเป็น | ความหมาย |
|---|---|---|
| `DASHBOARD_URL` | `"https://scicenter.rbru.ac.th/leqs-workshop/api/api.php?action=update_telemetry"` | บอร์ดใช้ที่อยู่นี้ส่งข้อมูลและรับคำสั่ง (ใช้แทนค่าที่เคยตั้งในพอร์ทัล) |
| `ENABLE_CUSTOM_SERVER` | `false` | ปิดการส่งไปยัง hub เก่า (`14.207.141.164:8000`) ซึ่งเคยส่งค่ารีเลย์เก่ามาทับคำสั่ง |
| `DEVICE_TOKEN` | รหัสลับของคุณ (ดูขั้นที่ 4) หรือ `""` ถ้าไม่ใช้ | ต้องตรงกับไฟล์บนเซิร์ฟเวอร์ |
| `WIFI_SSID` / `WIFI_PASSWORD` | Wi-Fi ที่ใช้ | หรือตั้งผ่านพอร์ทัลก็ได้ |

### ขั้นที่ 3 ใส่โปรแกรมลงบอร์ด

1. เสียบ USB เข้าบอร์ดและคอมพิวเตอร์
2. เปิด VS Code → **File → Open Folder** → เลือกโฟลเดอร์ `esp32-board`
3. กดไอคอน **✓ (Build)** รอจนขึ้น `SUCCESS`
4. กดไอคอน **→ (Upload)** รอจนขึ้น `SUCCESS` (ใช้เวลาประมาณ 30–40 วินาที)
5. กดไอคอนเต้ารับ (Serial Monitor) ความเร็ว **115200** เพื่อดูข้อความจากบอร์ด

หรือใช้ Terminal:
```
cd /Applications/XAMPP/xamppfiles/htdocs/handysense/esp32-board
pio run -t upload
pio device monitor -b 115200
```

ถ้าหน้าจอ Monitor ขึ้นแต่อักขระเพี้ยน แปลว่าตั้งความเร็วผิด ต้องเป็น 115200 (ค่า 9600 จะอ่านไม่ออก)

ข้อความที่แสดงว่าทำงานถูกต้อง:
- `[CloudData] >>> Sent Telemetry to Configured Dashboard [OK] (Code: 200) https://scicenter...`
- `[CmdPoll] OK 200 | relays now=0000 | https://scicenter...` (ขึ้นทุก ~5 วินาที ตัวเลข 4 หลักคือสถานะรีเลย์ 1–4)

### ขั้นที่ 4 ตั้ง Token กันข้อมูลปลอม (แนะนำ)

ต้องตั้ง **รหัสเดียวกันสองที่** และ **ต้องใส่โปรแกรมลงบอร์ดใหม่หลังแก้** ถ้าตั้งไม่ตรงกัน บอร์ดจะถูกปฏิเสธ (แดชบอร์ดขึ้น OFFLINE และ Serial Monitor ขึ้น 401)

1. คิดรหัส 1 ชุด ตัวอักษรอังกฤษและตัวเลขล้วน ยาว 16 ตัวขึ้นไป ไม่มีเว้นวรรค
2. สร้างไฟล์ข้อความชื่อ `device_token.txt` ข้างในใส่รหัสนั้นบรรทัดเดียว อัปโหลดไปที่ `/public/leqs-workshop/data/device_token.txt`
3. แก้ `#define DEVICE_TOKEN "รหัสของคุณ"` ใน `UserConfigs.h`
4. ทำขั้นที่ 3 (Upload) ซ้ำ
5. ตรวจ: Serial Monitor ต้องเห็น `Code: 200` ไม่ใช่ 401

ถ้ามีปัญหา: ลบไฟล์ `device_token.txt` ออกจากเซิร์ฟเวอร์ชั่วคราว (ระบบจะรับข้อมูลโดยไม่ตรวจรหัส) แล้วตรวจว่ารหัสสองที่ตรงกันทุกตัวอักษร

หมายเหตุ: Token ป้องกันเฉพาะ "บอร์ดส่งข้อมูล/ถามหาคำสั่ง" เท่านั้น ไม่ได้ป้องกันหน้าแดชบอร์ด (ดูหัวข้อ 9)

### ขั้นที่ 5 ทดสอบ

1. เปิด `https://scicenter.rbru.ac.th/leqs-workshop/dashboard/index.php` กด **Cmd+Shift+R** (รีโหลดไม่ใช้แคช)
2. มุมบนต้องขึ้น **LIVE** สีเขียว และตัวเลขเซนเซอร์เปลี่ยนไปเรื่อยๆ
3. ถอดอุปกรณ์ไฟฟ้าออกจากรีเลย์ก่อน แล้วกดสวิตช์รีเลย์ 1 ภายใน 1–3 วินาที ควรได้ยินเสียงรีเลย์ดังคลิกและขึ้นแถบแจ้งเตือน "เซิร์ฟเวอร์รับคำสั่งแล้ว"
4. Serial Monitor ต้องเห็น `[RelayActuator] >>> RELAY 1 (PUMP 1) -> ACTIVE [ON]`

## 5. ใช้งานหน้าแดชบอร์ดและหน้ามือถือ

หน้าแดชบอร์ด: `https://scicenter.rbru.ac.th/leqs-workshop/dashboard/index.php`
หน้ามือถือ: `https://scicenter.rbru.ac.th/leqs-workshop/mobile/index.php`
ทั้งสองหน้าส่งคำสั่งผ่านเซิร์ฟเวอร์ ใช้ข้ามเครือข่ายได้

### 5.1 แถบสถานะด้านบน (แดชบอร์ด)

| สถานะ | ความหมาย | ต้องทำอะไร |
|---|---|---|
| **LIVE** (เขียว) | ได้ข้อมูลจากบอร์ดล่าสุดภายในประมาณ 6 วินาที | ปกติ |
| **DELAYED** (เหลือง) | ข้อมูลล่าช้า 6–20 วินาที | รอสักครู่ ถ้ายังเหลืองให้ตรวจสัญญาณ Wi-Fi |
| **OFFLINE** (แดง) | ไม่ได้ข้อมูลเกิน 20 วินาที | ดูหัวข้อ 8 (ค่าที่เห็นเป็นค่าเก่า ห้ามใช้ตัดสินใจ) |

### 5.2 การ์ดค่าเซนเซอร์

สภาพอากาศ (อุณหภูมิ ความชื้น VPD), ความชื้นในดิน, กรด-ด่างและธาตุอาหาร (pH, N, P, K), แสงแดด, และการจัดเก็บข้อมูล (SD Card / ฐานข้อมูล) ค่าที่ไม่มีข้อมูลจะแสดง `--`

### 5.3 กราฟแนวโน้ม

แสดงอุณหภูมิ ความชื้น ความชื้นดิน ย้อนหลัง และเพิ่มจุดใหม่ทุกครั้งที่บอร์ดส่งข้อมูล กดปุ่ม Temp / Humidity / Soil Moist เพื่อซ่อนหรือแสดงแต่ละเส้น

### 5.4 สั่งรีเลย์ 4 ช่อง

1. กดสวิตช์ข้างชื่ออุปกรณ์ (ไปทางขวา = เปิด)
2. สวิตช์เปลี่ยนทันที และขึ้นแถบแจ้งเตือน **"เซิร์ฟเวอร์รับคำสั่งแล้ว"** แปลว่าคำสั่งถึงเซิร์ฟเวอร์แล้ว
3. บอร์ดจะรับคำสั่งภายใน 1–3 วินาที (ไม่ใช่ทันที) แล้วรีเลย์คลิก
4. ถ้าขึ้นแถบแดง **"สั่ง … ไม่สำเร็จ"** สวิตช์จะเด้งกลับ ข้อความใต้ชื่อบอกสาเหตุ (เช่น หมดเวลา, HTTP 500)
5. ปุ่ม **ปิดทั้งหมด** ปิดรีเลย์ที่เปิดอยู่ทุกช่อง
6. การกดสวิตช์ด้วยมือจะสลับเป็นโหมด Manual อัตโนมัติ

### 5.5 โหมดควบคุม

| โหมด | การทำงาน |
|---|---|
| **Manual** | สั่งเปิด-ปิดเองทั้งหมด |
| **Auto (SMART AUTO)** | บอร์ดเปิด-ปิดตามกฎเงื่อนไขที่ตั้งไว้ |
| **AI Smart (EDGE AI)** | บอร์ดตัดสินใจโดยโมเดล AI |

### 5.6 ข้อความเตือนใน Console (ไม่ต้องกังวล)

ข้อความ `Mixed Content ... http://10.x.x.x:8500/...` หรือ `Tailwind CDN should not be used in production` ไม่ใช่ข้อผิดพลาดที่กระทบการสั่งงาน ฉบับปรับปรุงนี้หลีกเลี่ยงการเรียกที่อยู่ภายในแล้ว

## 6. ใช้งานจอสัมผัสของบอร์ด

แถบเมนูด้านบนของจอมี 6 หน้า: **1. HOME, 2. DATA, 3. GRAPH, 4. RELAY, 5. SETUP** และ **ENG** (สลับภาษา)

- แตะแถบเมนูเพื่อเปลี่ยนหน้า
- หน้า **RELAY:** แตะกล่องรีเลย์เพื่อเปิด-ปิด (ระบบจะเข้าโหมด Manual)
- หน้า **GRAPH:** ดูกราฟย้อนหลัง
- หน้า **SETUP:** เปิด-ปิดพอร์ทัลตั้งค่า Wi-Fi
- เมื่อแตะจะมีกรอบขึ้นทันทีเพื่อยืนยันว่าบอร์ดรับการแตะ
- การเปลี่ยนรีเลย์จากแดชบอร์ดจะสะท้อนบนจอบอร์ดเองภายในไม่กี่วินาที
- การเปลี่ยนรีเลย์ที่จอบอร์ดจะถูกส่งขึ้นเซิร์ฟเวอร์ทันที และคำสั่งเก่าจากเซิร์ฟเวอร์จะไม่ทับภายใน 3 วินาที

1. บอร์ดมีอินเทอร์เน็ต (ฮอตสปอตมีสัญญาณและเปิดข้อมูลมือถือ)
2. `DASHBOARD_URL` ในเฟิร์มแวร์ชี้ไป scicenter (ขั้นที่ 2)
3. เปิดแดชบอร์ดจาก URL ของเซิร์ฟเวอร์ ไม่ใช่ `localhost`

**ทำไมต้องผ่านเซิร์ฟเวอร์:** อุปกรณ์คนละเครือข่ายมองไม่เห็นกันโดยตรง (IP เช่น `10.24.89.144` ใช้ได้เฉพาะวงของฮอตสปอตนั้น)

**ข้อจำกัด**
- คำสั่งจากแดชบอร์ดถึงบอร์ดช้ากว่าการต่อ Wi-Fi เดียวกัน ประมาณ 1–3 วินาที
- ใช้ข้อมูลอินเทอร์เน็ตของฮอตสปอตเล็กน้อยตลอดเวลา (ส่งข้อมูลทุก ~1.5 วินาที และถามหาคำสั่งทุก 1 วินาที)
- ถ้าบอร์ดหลุดอินเทอร์เน็ต คำสั่งจะไม่ถึงจนกว่าจะเชื่อมต่อใหม่

## 8. แก้ปัญหาเบื้องต้น

| อาการ | สาเหตุที่เป็นไปได้ | วิธีแก้ |
|---|---|---|
| เปิดหน้าแดชบอร์ดขึ้น HTTP ERROR 500 | สิทธิ์ไฟล์ผิด หรืออัปโหลดไม่ครบ | ตั้งสิทธิ์ไฟล์ `.php` เป็น `644` โฟลเดอร์เป็น `755` แล้วอัปโหลดใหม่ ถ้ายังไม่หายให้ขอดู `php_error_log` จากผู้ดูแลเซิร์ฟเวอร์ |
| สถานะ OFFLINE | บอร์ดไม่ส่งข้อมูล | ตรวจไฟบอร์ด, ฮอตสปอตมีอินเทอร์เน็ต, ดู Serial Monitor ว่ามี `Sent Telemetry ... scicenter [OK]` |
| ค่าเซนเซอร์ไม่เปลี่ยน | โฟลเดอร์ `data` เขียนไม่ได้ | ตั้งสิทธิ์ `data` เป็น `775` หรือ `777` |
| กดสวิตช์แล้วเด้งกลับ + แถบแดง | เซิร์ฟเวอร์ปฏิเสธหรือไม่ตอบ | อ่านข้อความในแถบแดง ตรวจสิทธิ์โฟลเดอร์ `data` และอินเทอร์เน็ตของคอมพิวเตอร์ |
| กดสวิตช์ได้ แถบเขียวขึ้น แต่รีเลย์ไม่ติด | บอร์ดไม่ได้ถามหาคำสั่งจาก scicenter | ดู Serial Monitor ต้องมี `[CmdPoll] OK 200 ... scicenter` ถ้าไม่มี ตรวจ `DASHBOARD_URL` และ Upload เฟิร์มแวร์ใหม่ |
| รีเลย์เคยติดแล้วเด้งกลับเป็น OFF เอง | `ENABLE_CUSTOM_SERVER` ยังเป็น `true` (hub เก่าส่งค่าทับ) หรือ `api.php` เป็นฉบับเก่าไม่มีล็อก | ตั้ง `ENABLE_CUSTOM_SERVER false`, อัปโหลด `api.php` ฉบับล่าสุด |
| Serial Monitor ขึ้น 401 | Token สองฝั่งไม่ตรง | แก้ให้ตรงกัน แล้ว Upload เฟิร์มแวร์ใหม่ หรือลบ `device_token.txt` ชั่วคราว |
| Serial Monitor เป็นอักขระเพี้ยน | ตั้งความเร็ว Monitor ผิด | ใช้ `pio device monitor -b 115200` |
| ขึ้น `error(-11): read Timeout` เป็นบางครั้ง | เซิร์ฟเวอร์ตอบช้าชั่วคราว | ไม่ต้องทำอะไร ถ้าเกิดถี่ให้ตรวจอินเทอร์เน็ตของฮอตสปอต |
| ขึ้น `Local PHP API ... connection refused` | `LOCAL_SERVER_URL` ชี้ไป Mac ในวง LAN บ้าน ซึ่งฮอตสปอตเข้าไม่ถึง | ไม่กระทบ (ฉบับล่าสุดปิดการส่งนี้ตอน `ENABLE_CUSTOM_SERVER false`) |
| SD Card ไม่ถูกตรวจพบ (`Card Failed`) | ไม่ได้ใส่การ์ด หรือการ์ดไม่รองรับ | ใส่การ์ดก่อนจ่ายไฟ ฟอร์แมตเป็น FAT32 ขนาดไม่เกิน 32 GB |
| อัปโหลดโปรแกรมไม่ผ่าน (ไม่เจอพอร์ต) | สาย USB ไม่ส่งข้อมูล / พอร์ตเสีย | เปลี่ยนสายหรือพอร์ต USB ปิด Serial Monitor ก่อนอัปโหลด |
| อัปโหลดไม่ผ่าน (Failed to connect) | บอร์ดไม่อยู่ในโหมดรับโปรแกรม | กดปุ่ม BOOT ค้าง → กด RESET หนึ่งครั้ง → ปล่อย BOOT แล้วอัปโหลดใหม่ |
| บอร์ดต่อ Wi-Fi ไม่ได้ | รหัสผ่านผิด หรือเป็น Wi-Fi 5 GHz | ใช้ Wi-Fi 2.4 GHz รอ 45 วินาทีให้พอร์ทัลเปิด แล้วตั้งค่าใหม่ |

## 9. ข้อควรระวังด้านความปลอดภัย

- **ไฟฟ้า:** รีเลย์ควบคุมอุปกรณ์ไฟฟ้า ปิดไฟและถอดปลั๊กก่อนต่อหรือแก้สายทุกครั้ง ผู้ที่ไม่มีความรู้ด้านไฟฟ้าควรให้ผู้เชี่ยวชาญต่อสายแรงดันสูง
- **ทดสอบแบบไม่มีโหลด:** ครั้งแรกทดสอบรีเลย์โดยไม่ต่อปั๊มหรือวาล์ว ฟังเสียงคลิกอย่างเดียว
- **การป้องกันแดชบอร์ด (สำคัญ):** ตอนนี้ใครรู้ URL ของแดชบอร์ดหรือหน้ามือถือก็สั่งรีเลย์ได้ Token ไม่ป้องกันส่วนนี้ ควรตั้งรหัสผ่านให้โฟลเดอร์ `dashboard` และ `mobile` ผ่านเมนู "Password Protect Directories" ของโฮสต์ หรือสอบถามผู้ดูแลระบบ
- **Token:** อย่าเผยแพร่รหัสและอย่าอัปโหลดไฟล์ `UserConfigs.h` ที่มีรหัส Wi-Fi หรือ Token ขึ้นที่สาธารณะหรือส่งต่อผู้อื่น
- **Serial Monitor:** ข้อความตอนบูตแสดงรหัส Wi-Fi ที่บอร์ดลองเชื่อมต่อ ห้ามคัดลอกหรือโพสต์ข้อความนั้นให้ผู้อื่น
- **เมื่อสถานะ OFFLINE:** ค่าที่เห็นเป็นค่าเก่า ห้ามใช้ตัดสินใจรดน้ำหรือควบคุมอุปกรณ์
